# Design System — v3.0 (Local Web App)

> Binding reference for all Node.js/Express local web applications.
> Use: local web apps (UI + API), personal and professional use.
> Inseparable from `layout.md`.
> Built on **Bootstrap 5.3**, compiled locally via Sass. All customization is a Sass variable override in `src/views/styles/_custom.scss`, compiled into `src/views/styles/app.scss` — never a runtime CSS token derivation.

**Visual language (v3.0)**: Bootstrap 5.3's own visual language, unmodified — soft shadows on floating layers (`.card`, `.dropdown-menu`, `.modal-content`), the default border-radius scale, native component states (`.active`, `:hover`, `:disabled`). The only per-project customization is the accent color (`$primary`). No custom token derivation, no bespoke motion signature.

## Changelog

| Version | Date       | Main change                                                                                       |
| ------- | ---------- | ---------------------------------------------------------------------------------------------------- |
| v3.0    | 2026-08-30 | **Replaced the custom token design system with Bootstrap 5.3** (npm, compiled locally via Sass): single `$primary` accent override (no more accent-tinted neutral derivation) · Bootstrap's default shadows/radius/transitions (depth-by-stroke and the `box-shadow` ban are abandoned) · signature underline / `placeUnderline()` removed — tab selection is the native `.nav-link.active` state · Bootstrap Icons (`bootstrap-icons` npm package, local font, `<i class="bi bi-*">`) replace the local Lucide sprite · dark mode via native `data-bs-theme` color-mode instead of the custom `[data-theme="dark"]` token block. |
| v2.0    | 2026-08-30 | (superseded) baseline for local-webapp, derived from the Electron generator v2.0 design system: `--radius` 5px · typography **system-ui** stack · **accent-tinted neutrals** (all neutral roles derived from the accent hue; explicit palette roles still win) · **semantic colors derived per project** (fixed hue anchors, harmonized ±6° toward the accent; info = accent) · hover on neutral elements = **border strengthening** · easing `--ease-out` (decelerate) 160/240ms · **signature gesture**: sliding underline (tabs / horizontal nav) · Lucide icons (stroke 1.75px); `--icon-*` consume semantic/primary tokens · floating layers marked by `--border-strong` (shadows forbidden) |

Every generated application references the active version in its `README.md`.

## 1. BOOTSTRAP INTEGRATION — FILES AND COMPILATION

| File                                    | Role                                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `src/views/styles/_custom.scss`         | `$primary` override (+ any other validated Bootstrap Sass variable override), imported **before** `bootstrap/scss/bootstrap` |
| `src/views/styles/app.scss`             | Entry point: `@import "custom";` then `@import "bootstrap/scss/bootstrap";`, plus any residual custom rule Bootstrap does not cover |
| `public/css/app.css`                    | Compiled output (generated by `npm run build:css`, committed, never hand-edited)          |
| Bootstrap Icons (`bootstrap-icons` npm) | Served directly from `node_modules/bootstrap-icons/font/` via a dedicated Express static route — no copy step |

```scss
// _custom.scss — project accent override, imported before Bootstrap
$primary: #4682B4;   // Phase 1 accent choice — omit this line for the Bootstrap default (#0d6efd)
```

```scss
// app.scss — entry point
@import "custom";
@import "bootstrap/scss/bootstrap";

// project-specific residual rules (only what Bootstrap does not cover) below
```

Compilation: `npm run build:css` (`sass src/views/styles/app.scss:public/css/app.css`). Full detail: `@rules/css.md`.

**Zero CDN reaffirmed**: `bootstrap` and `bootstrap-icons` are npm dependencies, compiled/served locally — never a CDN `<link>`/`<script>`.

## 2. THEME / ACCENT

Principle: **the Bootstrap 5.3 standard theme drives every color** — no accent-tinted neutral derivation, no per-project semantic color harmonization. The only per-project override is the accent, `$primary`, and it is optional.

- No accent chosen in Phase 1 → no override; `$primary` stays the Bootstrap default (`#0d6efd`).
- Accent chosen → a single line in `_custom.scss`. Bootstrap's own Sass recomputes `--bs-primary`, `--bs-primary-rgb`, every hover/active/focus derivative, and the color-mode variants automatically at compile time — no manual HSL derivation.

### Accent catalog (Phase 1)

`/local-webapp-p1-scoping` presents these. Each preset is a single hex value — no optional overrides beyond it (unlike the old v2.0 system).

| Name                    | Accent (`$primary`) |
| ------------------------- | ---------------------- |
| Steel Blue (default)     | #4682B4               |
| Teal                     | #0D9488               |
| Forest                   | #059669               |
| Slate                    | #4F46E5               |
| Amber                    | #B45309               |
| Ruby                     | #BE123C               |
| Bootstrap default        | (no override — `#0d6efd`) |

### Semantic colors (success/warning/danger/info)

Bootstrap's own standard `$success`/`$warning`/`$danger`/`$info` — **not derived or harmonized toward the accent**. This is an explicit, intentional simplification versus v2.0: semantic colors stay Bootstrap's own hues, recognizable across every Bootstrap-based product.

### Contrast check (WCAG AA, non-blocking)

Compute `$primary` against white and against near-black (the two candidate `--bs-*` text-on-primary outcomes). If the ratio fails AA, report it (`color — ratio — target`) and ask the user to confirm or adjust before continuing. Bootstrap's own semantic colors are pre-validated AA by the framework and are not re-checked here.

## 3. TYPOGRAPHY

Bootstrap's default font stack (`$font-family-sans-serif`) — zero embedded font, zero dependency; the app looks native to the browser it runs in, same principle as before, now delegated to Bootstrap's own stack.

Sizes and weights follow Bootstrap's utility classes and heading elements — no custom `--font-*` token table:

| Need                | Bootstrap mechanism                          |
| ---------------------- | ------------------------------------------------ |
| Headings              | `<h1>`–`<h6>` or `.h1`–`.h6`                     |
| Body text sizes       | `.fs-1`–`.fs-6`, `.small`                        |
| Weight                | `.fw-normal` / `.fw-medium` / `.fw-semibold` / `.fw-bold` |
| Line-height           | `.lh-1` / `.lh-sm` / `.lh-base` / `.lh-lg`       |

A project-level typography override (e.g. a different `$font-family-sans-serif` or `$font-size-base`) is a validated Phase 1 decision, added to `_custom.scss`.

### Numerals

Tables, statusbar counters, and any column of figures set `font-variant-numeric: tabular-nums` (residual rule in `app.scss` — Bootstrap has no utility for this).

## 4. SPACING

Bootstrap's spacing scale (`$spacer`, default 1rem) drives every margin/padding/gap via utility classes — no custom `--spacing-*` token table.

| Need                  | Bootstrap utility                          |
| ------------------------ | ---------------------------------------------- |
| Micro-spacing           | `.p-1` / `.m-1` / `.gap-1` (0.25rem)          |
| Compact inner padding    | `.p-2` (0.5rem)                               |
| Standard padding         | `.p-3` (1rem)                                 |
| Inter-element spacing    | `.gap-3` / `.mb-3`                            |
| Main content padding     | `.p-4` (1.5rem)                               |
| Major separation         | `.p-5` (3rem)                                 |

A project-level spacing override (a different `$spacer`) is a validated Phase 1 decision, added to `_custom.scss`.

## 5. COMPONENT SIZES

### Structural sizes (no Bootstrap equivalent — residual Sass variables in `_custom.scss`)

| Variable                | Value  | Usage                      |
| -------------------------- | ------ | ---------------------------- |
| `$statusbar-height`      | 28px   | Statusbar height (no Bootstrap component covers this) |
| `$statusbar-bg`           | `$gray-100` (light) / `$gray-800` (dark) | Statusbar background |
| `--bs-navbar-height`      | Bootstrap default (~56px expanded) | Topbar (`.navbar`) — not overridden unless validated |

### Offcanvas (drawer) — Bootstrap native

| Variable                  | Value                                     |
| ---------------------------- | ---------------------------------------------- |
| `--bs-offcanvas-width`     | Bootstrap default, **400px** — not overridden by default (replaces the old fixed 320px; a custom width is a Phase 3 choice, documented as an explicit `_custom.scss` override when chosen) |

### Icon sizes

Bootstrap Icons scale with `font-size` — no fixed icon-size tokens. Typical usage: `fs-5` (~20px, standard), `fs-4` (~24px, navbar/topbar).

### Dynamic sizes — general principle

Unchanged principle: no component has a fixed height/width beyond the documented structural exceptions above. Bootstrap's own components (buttons, form controls, cards, tables) size to content + Bootstrap's own padding scale by default.

## 6. SHAPE, SHADOWS, BORDERS — BOOTSTRAP STANDARD (replaces "depth by stroke")

**Bootstrap's own conventions apply, unmodified.** Floating layers (`.dropdown-menu`, `.modal-content`, `.toast`, `.card`) carry Bootstrap's native shadow utilities and component-level box-shadow. `box-shadow` is a normal, expected CSS property in this system.

> **Deprecation note (v2.0 → v3.0)**: depth-by-stroke, the uniform 5px `--radius` token, and the blanket `box-shadow` ban are abandoned. Bootstrap expresses depth through a light shadow + its own default radius scale, and this framework no longer overrides that language.

| Variable            | Value                                        |
| ---------------------- | ------------------------------------------------ |
| `$border-radius`     | Bootstrap default (0.375rem) — override in `_custom.scss` only if validated in Phase 1 |
| `$box-shadow*`       | Bootstrap defaults (`.shadow-sm`, `.shadow`, `.shadow-lg`) — used freely on residual custom surfaces (e.g. the statusbar) where it improves legibility |

---

## 7. TRANSITIONS

Bootstrap's own transition variables (`$transition-base`, `$transition-fade`, `$transition-collapse`) drive every native component animation (collapse, fade, offcanvas slide) — no custom easing token.

> **Deprecation note**: the custom `--ease-out` cubic-bezier easing and the "signature gesture" motion policy are abandoned. There is no longer a single sanctioned expressive movement in the system — every native Bootstrap component transition is used as shipped.

## 8. FOCUS

Bootstrap 5.3's native focus-visible styling and the `.focus-ring` utility apply — no custom `--focus-ring` token.

```css
/* Bootstrap 5.3 native — no override needed unless validated in Phase 1 */
:focus-visible { /* handled by Bootstrap component-level :focus styles + .focus-ring utility */ }
```

## 9. INTERACTIVE COMPONENT STATES (replaces the v2.0 "signature gesture" section)

Native Bootstrap component states apply throughout — no custom hover/active model, no signature gesture:

| State                    | Mechanism                                                                 |
| --------------------------- | ------------------------------------------------------------------------------ |
| `default`                 | Bootstrap component default style                                            |
| `:hover`                  | Native Bootstrap hover (e.g. `.nav-link:hover`, `.btn:hover`, `.list-group-item:hover`) |
| `:active` (transient)     | Native Bootstrap `:active` styling                                           |
| `.active` (selected)      | Native Bootstrap `.active` class (`.nav-link.active`, `.list-group-item.active`, `.page-item.active`) — carries `aria-current="page"` where applicable |
| `:disabled` / `.disabled` | Native Bootstrap disabled styling                                            |
| `:focus-visible`          | Native Bootstrap focus styling (§8)                                          |

> **Deprecation note (v2.0 → v3.0)**: the "signature gesture" — a sliding underline on tabs/horizontal navigation, driven by a `placeUnderline()` script writing `--underline-x`/`--underline-w` — is **removed entirely**. Tab selection is the native `.nav-link.active` state, with no JS-positioned visual anywhere in the system.

Native Bootstrap button classes — no custom variant table.

| Variant    | Class                     |
| ------------ | ---------------------------- |
| Primary    | `.btn-primary`             |
| Secondary  | `.btn-secondary`           |
| Danger     | `.btn-danger`               |
| Ghost      | `.btn-outline-secondary` (replaces the old `.btn-ghost`) |

## 11. ICONS — BOOTSTRAP ICONS (replaces Lucide)

Icon set: **Bootstrap Icons** (`bootstrap-icons` npm package) — local font, served from `node_modules/bootstrap-icons/font/` via a dedicated Express static route. Zero CDN, no external resource loaded at runtime.

```html
<!-- Usage in a view (server-rendered template) -->
<i class="bi bi-house" aria-hidden="true"></i>
```

| Need              | Mechanism                                                        |
| -------------------- | --------------------------------------------------------------------- |
| Icon color         | Bootstrap text-color utilities: `text-primary`, `text-success`, `text-warning`, `text-danger`, `text-body-secondary` (replaces `--icon-*` tokens) |
| Icon size           | `font-size` — `fs-5` (~20px), `fs-4` (~24px), or a literal `font-size` where the surrounding context already sets one |

> No sprite to embed or maintain — the icon font ships as a single dependency. Any icon name used in a template must be a real Bootstrap Icons glyph name (`bi-*`) — never invented.

## 12. CSS/SASS APPLICATION RULES (replaces the v2.0 CSS application rules)

1. **Bootstrap classes/components first.** A visual need is expressed with a Bootstrap utility class or native component before any custom rule is written.
2. **Zero reinvention of an existing Bootstrap component.** Never hand-build a custom `.btn`, `.card`, `.modal`, `.toast`, `.navbar`, or `.offcanvas` — the native component is used, even when it requires more markup than a bespoke `<div>`.
3. **Residual custom rules confined to `app.scss`**, in a clearly marked block below the Bootstrap imports — only for what Bootstrap does not cover (e.g. the statusbar).
4. **`$primary` is the default single point of color customization.** Any further Bootstrap Sass variable override is a validated Phase 1 decision, documented in `docs/specs/01-scoping.md`.
5. **Dark mode is `data-bs-theme`** — see §14. No `[data-theme]` selector, no `@media (prefers-color-scheme)` anywhere in the codebase.

Full detail and anti-patterns: `@rules/css.md`.

## 13. ACCESSIBILITY

Target: **WCAG 2.1 level AA** — Bootstrap 5.3's own components are designed AA-compliant by default. Project-specific verification is narrowed to what the project actually customizes:

| Criterion            | Rule                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `$primary` contrast   | ≥ 4.5:1 against its text-on-primary color (white or near-black) — checked in Phase 1 (§2)          |
| Bootstrap semantic colors | Pre-validated AA by Bootstrap itself — not re-checked per project                                |
| Focus visibility      | Native Bootstrap focus styling always visible, never removed                                        |
| Reduced motion        | Bootstrap 5.3 already respects `prefers-reduced-motion` on its own JS-driven transitions — no project-level override needed unless a residual custom animation is added |

## 14. DARK MODE — `data-bs-theme`

Dark mode uses Bootstrap 5.3's **native color-mode mechanism**: `data-bs-theme="dark"` / `data-bs-theme="light"` on `<html>`. Every `--bs-*` variable Bootstrap ships is automatically redefined per mode — **zero manual token redefinition** for standard colors.

```html
<html data-bs-theme="light"> <!-- or "dark" -->
```

```js
// public/js/theme.js — principle
document.documentElement.setAttribute("data-bs-theme", theme); // "light" | "dark"
localStorage.setItem("theme", theme); // or a server-persisted preference — layout.md §10
```

**Accent overridden in both modes**: `$primary` set in `_custom.scss` applies identically in light and dark — Bootstrap derives the appropriate hover/active/focus shades for each mode automatically at compile time. If a project genuinely needs the accent itself to differ between modes (rare), that is a targeted, documented exception:

```scss
// app.scss — residual, rare exception (documented in docs/specs/04-architect.md if used)
[data-bs-theme="dark"] { --bs-primary: #6ea4c9; }
```

> **Deprecation note**: the custom `[data-theme="dark"]` token-redefinition block is removed entirely — replaced by Bootstrap's native color-mode attribute and its own variable set.

## 15. LAYERING (z-index)

No custom `--z-*` token scale — Bootstrap's own z-index variables cover every overlay:

| Bootstrap variable      | Element                          |
| -------------------------- | ------------------------------------ |
| `$zindex-dropdown`       | Dropdown / context menu             |
| `$zindex-fixed`          | Fixed topbar/statusbar              |
| `$zindex-offcanvas`      | Drawer (`.offcanvas`)               |
| `$zindex-modal`          | Modal                                |
| `$zindex-toast`          | Toasts (`.toast-container`)         |

No hardcoded `z-index` outside these Bootstrap-native variables.
